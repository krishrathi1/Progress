## Definition

**Memory management** is the part of the operating system that controls and coordinates main memory (RAM). It tracks every byte, decides which process gets memory and how much, allocates space when a process needs it, and reclaims it when the process finishes.

## Why It Matters

- The CPU can only execute instructions and access data that reside in main memory, so a process must be (at least partly) loaded into RAM to run.
- RAM is limited and shared by many processes, so the OS must allocate it fairly and efficiently.
- Programs must be protected from one another so a bug in one process cannot corrupt another's memory.

## Key Responsibilities

- **Allocation & deallocation** – give memory to processes on request and free it afterward.
- **Address translation** – map a program's logical (virtual) addresses to physical addresses.
- **Protection** – prevent a process from accessing memory outside its region.
- **Sharing** – let processes share code/data safely (e.g., shared libraries).
- **Tracking** – maintain the status (free/allocated) of every memory region.

## Logical vs Physical Address

```text
 CPU generates          MMU (hardware)         Actual RAM
 Logical Address  --->  translation      --->  Physical Address
   (virtual)            + protection            (real location)
```

- **Logical address**: generated by the CPU as seen by the program.
- **Physical address**: the real location in RAM.
- The **Memory Management Unit (MMU)** translates logical to physical at runtime.

## Comparison

| Concept | Logical Address | Physical Address |
|---|---|---|
| Generated by | CPU / program | Memory unit |
| Also called | Virtual address | Real address |
| Visible to user | Yes | No |
| Range | Logical address space | Physical address space |

## Techniques Overview

- **Contiguous allocation**: each process gets one continuous block.
- **Paging**: divide memory into fixed-size frames/pages.
- **Segmentation**: divide by logical segments (code, stack, heap).
- **Virtual memory**: run processes larger than physical RAM using disk.

## Key points

- Memory management maximizes CPU utilization and multiprogramming.
- Address binding can happen at compile, load, or execution time; execution-time binding needs an MMU.
- Protection and relocation are core goals, usually via base and limit registers.
- Good memory management minimizes fragmentation and overhead.
